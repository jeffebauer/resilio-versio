# 0043 — Kick removed; the button throws and taps tempo

**Status:** Proposed, 5 Oct 2026 (the owner's decisions of 5 Oct; branch `feat/button-throw-tap`; merge after the owner's OK). Supersedes **ADR 0005** (Kick fixed strength), **ADR 0013** (hold-for-rattle deferred) and **ADR 0016** (Kick = thud + crash). Amends **ADR 0039** (the throw: the button throws too; a new exit gesture) and **ADR 0041** (echo mode: the button taps the tempo). SPEC v1.0.37. Numbers: `core/params/ThrowHold.h` (the gesture), `core/params/EchoVoicing.h` (the clock). Code: `Tank::button()`, `dsp/EchoClock.h`, `plugin/ButtonLink.h`. Tests: `host/tests/test_button.cpp`.

**Context:**
- Since ADR 0039 the gate is the throw, and the button was the Kick: a simulated knock on the tank (a low thump, a noise burst and a forced maximal splash with its Clatter crash). The throw has become the move the owner plays; the Kick was one more thing on a small panel.
- The Kick, its voice and the Clatter took ~3–4 KB of flash (Kick-related functions ~2.3 KB in the release ELF plus inlined code) on a release image at 97 % of 128 KB, and a little CPU.
- Leaving throw mode was "hold KICK 1 s": a gesture on a button that also played. Once the button throws, any single-press gesture would collide with playing it: the owner taps quickly or slowly and holds long throws as performance moves.
- Echo mode (ADR 0041) takes its tempo from a gate clock or the DAW. Without a clock patched there was no way to set it on the module.

**Decision (owner, 5 Oct 2026):**
1. **Remove the Kick everywhere** (module and plugin): no Kick voice (thump + burst), no Clatter (it served only the Kick's crash since ADR 0032), no MIDI Kicks. The Splash's Jolt, Clang and Bite stay: they are a hit's own splash.
2. **The button, SPRINGS 1–2: a manual throw.** While held, the Springs' send is open, exactly like the gate held high (same 2 ms / 15 ms ramps). The first press switches throw mode on, like the gate's first rising edge, so with nothing patched the button alone is a hand-throw instrument: press = send open, release = closed, the tail rings on. In throw mode the send is open while the gate is high **or** the button is held.
3. **Leaving throw mode: tap, then press again and hold 2 s** (SPRINGS 1–2 only). Then throw mode is off (the send glides open, 2 ms) and the LEDs give the existing white blink (only if it was on; the blink keeps fa54cb6's unsigned elapsed-time timer). No single press of any length exits. The exact rule (`ThrowHold.h`):
   - the first tap is short: released within **0.35 s** (`kExitTapMaxSeconds`);
   - the second press comes within **0.35 s** of that release (`kExitGapSeconds`);
   - the first tap stands alone: no release in the 0.35 s before it, so a run of fast taps that ends in a long throw is never read as a double tap;
   - the second press is held **2 s** (`kThrowExitHoldSeconds`), checked on the Tank's 32-sample control grid (within 0.7 ms, any block size).

   Why 0.35 s: a relaxed, deliberate double tap fits with room (desktop double-click defaults are 0.4–0.5 s; a quick one is 0.1–0.2 s), while slow tapping (quarter notes at 85 bpm or slower held half the beat leave gaps of 0.35 s or more) never pairs up, and faster runs fail the stands-alone rule. Shorter would make the gesture fiddly; longer would let more rhythms pair up (the stands-alone rule and the 2 s hold still guard them). Both taps throw like any press while they happen (the second holds the send open as it counts, and after the exit the send simply stays open), so the gesture never mutes anything.
4. **The button, SPRINGS 3 (echo mode): tap tempo.** Each press is a tap; one tap interval = one beat, read by the same code as the gate clock (`dsp::EchoClock`: the median of the last three intervals, 30–300 bpm, ±2 % ignored, a bounce ignored, a longer gap starts the count again), with TENSION's same seven divisions. A press in position 3 never throws. Presses in 1–2 never tap.
   - **Lost-clock fallback, adapted for taps:** the gate clock is lost 2.25 beats after its last pulse (≤ 2.5 s), because a stopped sequencer means "no clock". Read literally for taps, the tempo would vanish two beats after you stop tapping, which defeats tap tempo. So a tapped tempo **holds** after the taps stop, and the fallback is a **lone tap**: one tap with no second within the slowest interval (~2 s at 30 bpm) lets the tempo go, back to TENSION's free time. Before the first interval locks, a tap times out exactly like a first gate pulse. (One line to change, `EchoClock::update(now, holdTempo)`, if the owner wants the literal rule.)
   - **With a gate clock too: the last to set a tempo wins.** Each clock counts when its tempo is set or changed; of the two that are locked, the one that changed last is used. So taps take over from a steady gate clock (its pulses don't change its tempo), a gate clock that changes tempo takes back over, and if the gate clock is lost the tapped tempo (still held) comes back rather than free time. Edges and taps count on their exact samples, so any block size reads the same tempo.
5. **The gate jack stays digital on/off** (GateIn on a digital pin: no level, no jack detection): THROW in SPRINGS 1–2, the echo's clock in 3, as before. No CV-level throw (owner's call).

**Plugin and Renderer:**
- **Panel:** the KICK button is now the **THROW** button with the module's behaviour (held = throw in 1–2, the double-tap exit with the white blink, taps = tempo in 3). The latching switch beside it is labelled **GATE**: it is still the `throw_gate` parameter (named THROW in the host's list, unchanged, so saved sets keep it). There was **no KICK parameter** in ParamSpec (the Kick was a panel button and MIDI, never a host parameter), so no key was renamed, repurposed or removed and no saved Ableton slot moves.
- **Taps vs the host's tempo:** in a DAW that gives a tempo (Ableton always does, playing or not) the host's tempo wins and taps in position 3 change nothing; they only count in a host with no tempo.
- **MIDI notes are the gate** (they fired Kicks): any note on any channel, velocity ignored, held = gate high (the gate stays high while any note is held), sample-accurate; each note-on is also a clock edge, as the jack's rising edge. Picked over "MIDI does nothing" because it lets an Ableton clip sequence throws to the sample (a held note per throw) the way a sequencer's gate does on the module, and it keeps the plugin a faithful twin of the jack. The THROW / GATE switch and the notes share the one gate: the last change wins.
- The panel's presses reach the audio thread through `plugin/ButtonLink.h` (JUCE-free, so the host test checks it): at the start of each block; a click shorter than a block is a press at the block's start and a release at its last sample.
- **Renderer automation:** `"buttons": [[press, release], ...]` (seconds, sample-accurate) replaces `"kicks"`, which is now refused with a pointer here; `"gates"`, `"clocks"`, `"clock_bpm"` and `"throw_exits"` (still `Tank::exitThrowMode()`) are unchanged. The Kick-only presets went: `presets/sweeps/m7_kick.json` (an automation file of Kicks on silence) and `tone_after_kick_t100.json` with its automation `tone_after_auto_kick.json`.

**Consequences:**
- The "drip / kick" of SPEC §2.1 (hitting the tank: a huge low thump and a chaotic crash) is no longer something the module makes on its own. A hard hit fed in still splashes, jolts and, in KICKED, rattles; the button now does dub's other move with a spring, the throw.
- Flash (merged with `main` f57adca: round 5, tank voicing 8): release **125,172 B** (main 128,092: **−2,920 B**, 5,900 B free), profile **127,000 B** (main 130,384: **−3,384 B**, 4,072 B free); against earlier mains −2,072 / −1,800 (6955ff7) and −2,040 / −1,592 (fedd412). the saving grew with round 5 (its voicing-8 code also had Kick and Clatter paths to drop); the button's gesture and tap tempo cost back part of what the Kick and the Clatter freed. No new fused multiply-adds (the only `vfma` in the release image are libm's and libDaisy's).
- CPU: see the commit message / firmware README (desktop, whole Renderer runs against `main`).
- A press after the exit switches throw mode on again, as a rising edge does: to stay out of it, don't touch the button (or patch nothing in the gate).
